everpure.flasharray.purefa_preset module – Manage Fusion fleet block workload presets

Note

This module is part of the everpure.flasharray collection (version 1.46.0).

You might already have this collection installed if you are using the ansible package. It is not included in ansible-core. To check whether it is installed, run ansible-galaxy collection list.

To install it, use: ansible-galaxy collection install everpure.flasharray. You need further requirements to be able to use this module, see Requirements for details.

To use it in a playbook, specify: everpure.flasharray.purefa_preset.

New in everpure.flasharray 1.46.0

Synopsis

  • Create, replace, rename or delete Fusion fleet workload presets for block (FlashArray volume) workloads.

  • A preset is the template that everpure.flasharray.purefa_workload builds a workload from. It names a placement, the volumes to provision there, and optionally QoS limits, snapshot schedules, replication schedules, deploy-time parameters and tags.

  • The preset is managed declaratively and as a whole. Every run compares the preset you describe with the preset on the fleet and, when they differ, replaces the fleet’s copy with yours. See the notes for what that means for sections you leave out.

  • Only block presets are supported. File presets (directories, exports, quotas), and the bucket and lifecycle sections of newer Purity releases, are not managed by this module, and it refuses to replace a preset that has them.

Requirements

The below requirements are needed on the host that executes this module.

  • python >= 3.3

  • purestorage >= 1.19

  • py-pure-client >= 1.88.0

  • netaddr

  • requests

  • pycountry

  • urllib3

Notes

Note

  • Requires Purity//FA REST API 2.51 or higher, 2.54 for placement.targets.

  • Writing a preset needs a fleet-wide identity, that is a directory user, and an API token made for it. A token made for a local array user can read presets but every write fails with a 403 error, and the module says so.

  • The preset is replaced as a whole. Anything you leave out of the task is empty after the run. That is how a section is removed, and it also means an edit made to the preset in the GUI that the task does not describe is lost the next time the task changes something. The one exception is a configuration’s naming template, which is kept when the task leaves it out.

  • The module decides whether anything changed by comparing the preset on the fleet, read back from the array, with the preset described by the task. The array spells numbers as text and fills in defaults, which are not counted as differences. A naming template the task leaves out is taken from the configuration of the same name and kind on the fleet, both for the comparison and for the request, so a replacement made for another reason does not reset it.

  • Parameter references. Fields that accept one take a value such as {{ parameters.volume_size }}, which the array fills in when a workload is created. Ansible would expand that text itself, so it has to be protected, either by writing the value with the !unsafe tag in YAML or by wrapping it in {% raw %} and {% endraw %}. See the examples.

  • Most mistakes that the array would report one at a time, or not at all, are found before any request is made, and reported together. These are references to configurations that do not exist, configurations nothing uses, a name used by two configurations, parameters that are undefined or unused, and the limits. The array does not check placement.storage_class or replications.target, so a wrong value is found only when a workload is created from the preset.

  • The module cannot predict whether the array will accept the preset in check mode, only whether it would change. In particular it cannot tell whether placement.targets or skip_verify_deployable would be accepted.

  • Supports check_mode and --diff. The difference shown is between the preset on the fleet and the preset described by the task, both in the module’s normalised form, not the exact request.

  • Preset names are scoped to the fleet. The module always reads and writes through the fleet, wherever the connection is made.

  • This module requires the py-pure-client Python library.

  • Additional Python libraries may be required for specific modules.

  • You must set PUREFA_URL and PUREFA_API environment variables if fa_url and api_token arguments are not passed to the module directly.

  • Token-based authentication (id_token, or private_key_file with client_id, key_id, issuer and username) may be used as an alternative to api_token, and requires a matching API Client registered on the array via everpure.flasharray.purefa_apiclient.

Examples

- name: Create a preset with one placement and one volume
  everpure.flasharray.purefa_preset:
    name: app-small
    workload_type: Custom
    description: One 1 GiB volume
    placement:
      storage_class:
        name: flasharray-x
    volumes:
      - name: data
        provisioned_size: '1073741824'
    fa_url: 10.10.10.2
    api_token: e31060a7-21fc-e277-6240-25983c6c4592

- name: Create a preset with QoS, a snapshot schedule and a replication schedule
  everpure.flasharray.purefa_preset:
    name: app-protected
    workload_type: PostgreSQL
    placement:
      name: pg-placement
      qos: pg-qos
      storage_class:
        name: flasharray-x
    qos:
      - name: pg-qos
        iops_limit: '50000'
        bandwidth_limit: '1073741824'
    snapshots:
      - name: hourly
        rules:
          - every: '3600000'
            keep_for: '86400000'
    replications:
      - name: offsite
        target:
          name: arrayB
        rules:
          - every: '86400000'
            keep_for: '604800000'
            at: '7200000'
    volumes:
      - name: data
        count: '2'
        provisioned_size: '107374182400'
        snapshots: [hourly]
        replications: [offsite]
    tags:
      - key: app
        value: postgres
    fa_url: 10.10.10.2
    api_token: e31060a7-21fc-e277-6240-25983c6c4592

- name: Create a preset that asks for the size, the storage class and a tag at deploy time
  everpure.flasharray.purefa_preset:
    name: app-flexible
    workload_type: Custom
    parameters:
      - name: vol_size
        type: integer
        subtype: size
        default: '1073741824'
        minimum: 1073741824
        maximum: 1099511627776
      - name: tier
        type: resource_reference
        resource_type: storage-classes
        default: flasharray-x
      - name: env
        type: string
        default: dev
        allowed_values: [dev, test, prod]
    placement:
      storage_class:
        parameter: tier
    volumes:
      - name: data
        # A parameter reference has to be protected from Ansible's own templating.
        provisioned_size: !unsafe '{{ parameters.vol_size }}'
    tags:
      - key: environment
        # The same protection written as a raw block.
        value: "{% raw %}{{ parameters.env }}{% endraw %}"
    fa_url: 10.10.10.2
    api_token: e31060a7-21fc-e277-6240-25983c6c4592

- name: Remove the snapshot schedule by leaving it out, because the whole preset is replaced
  everpure.flasharray.purefa_preset:
    name: app-protected
    workload_type: PostgreSQL
    placement:
      name: pg-placement
      qos: pg-qos
      storage_class:
        name: flasharray-x
    qos:
      - name: pg-qos
        iops_limit: '50000'
    volumes:
      - name: data
        provisioned_size: '107374182400'
    fa_url: 10.10.10.2
    api_token: e31060a7-21fc-e277-6240-25983c6c4592

- name: Rename a preset and show what would change
  everpure.flasharray.purefa_preset:
    name: app-small
    new_name: app-tiny
    workload_type: Custom
    placement:
      storage_class:
        name: flasharray-x
    volumes:
      - name: data
        provisioned_size: '1073741824'
    fa_url: 10.10.10.2
    api_token: e31060a7-21fc-e277-6240-25983c6c4592
  check_mode: true
  diff: true

- name: Load a preset that no fleet member can deploy yet
  everpure.flasharray.purefa_preset:
    name: app-draft
    workload_type: Custom
    skip_verify_deployable: true
    placement:
      storage_class:
        name: flasharray-x
    volumes:
      - name: data
        provisioned_size: '1073741824'
    fa_url: 10.10.10.2
    api_token: e31060a7-21fc-e277-6240-25983c6c4592

- name: Delete a preset
  everpure.flasharray.purefa_preset:
    name: app-small
    state: absent
    fa_url: 10.10.10.2
    api_token: e31060a7-21fc-e277-6240-25983c6c4592

diff

dictionary

The preset before and after, as text, in the module’s normalised form. A naming template the task leaves out is shown on both sides as it is on the fleet. On a rename the old and new names are part of the text, so the change shows even when nothing else differs.

Returned: when running with --diff

preset

dictionary

Describes the preset after the task.

Returned: success

changed_sections

list / elements=string

The top-level sections of the preset that the run changed, or in check mode would change. Empty when nothing changed. A create or delete lists every section that was set or unset.

Returned: success

Sample: ["volume_configurations", "workload_tags"]

name

string

Name of the preset. This is the new name after a rename. It is the name that was asked for after a delete, or in check mode when the preset does not exist yet.

Returned: success

Sample: "app-small"

revision

integer

Revision counter the array keeps for the preset. It is null after a delete, and in check mode where the preset does not exist yet. The counter is increased by the array and is not a reliable sign of a change. Use changed.

Returned: success

Sample: 3
